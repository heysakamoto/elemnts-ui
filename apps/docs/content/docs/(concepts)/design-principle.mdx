## Core Principles

Moto UI is built on a set of core principles that prioritize semantic clarity, accessibility, composition, and a superior developer experience.

### Semantic Intent

We prioritize semantic naming over purely visual descriptions. Instead of `solid` or `outline`, we use `primary`, `secondary`, and `tertiary` to define a clear visual hierarchy, inspired by [Uber's Base Design System](https://base.uber.com/6d2425e9f/p/756216-button).

```tsx
import { Stack, Button } from "@moto-ui/react";

export function App() {
  return (
    <Stack direction="row" gap="8">
      <Button variant="primary">Primary Action</Button>
      <Button variant="secondary">Secondary Action</Button>
      <Button variant="tertiary">Tertiary Action</Button>
    </Stack>
  );
}
```

### Accessibility First

Built on top of [Ark UI](https://ark-ui.com), Moto UI components follow WAI-ARIA authoring practices. We ensure WCAG 2.1 AA compliance by providing automatic ARIA attributes, full keyboard navigation, and managed focus states out of the box.

```tsx
import { SegmentGroup, Icon } from "@moto-ui/react";

<SegmentGroup defaultValue="list">
  <SegmentGroup.Indicator />
  <SegmentGroup.Item value="list">
    <SegmentGroup.ItemText>List View</SegmentGroup.ItemText>
    <SegmentGroup.ItemHiddenInput />
  </SegmentGroup.Item>
  <SegmentGroup.Item value="grid">
    <SegmentGroup.ItemText>Grid View</SegmentGroup.ItemText>
    <SegmentGroup.ItemHiddenInput />
  </SegmentGroup.Item>
</SegmentGroup>
```

### Compositional Flexibility

Using the **Compound Component** pattern, we give you full control over the rendering and order of internal elements. Moto UI components support both **dot notation** and **named exports**, allowing you to choose the style that fits your workflow.

```tsx
import { Accordion, Text } from "@moto-ui/react";

// Using Dot Notation
<Accordion defaultValue={["1"]}>
  <Accordion.Item value="1">
    <Accordion.ItemTrigger>Is it accessible?</Accordion.ItemTrigger>
    <Accordion.ItemContent>
      <Text>Yes! It follows WAI-ARIA patterns.</Text>
    </Accordion.ItemContent>
  </Accordion.Item>
</Accordion>
```

### Consistent Behavior

All components follow predictable patterns for sizing (`xs` to `xl`), variants, and customization. Whether you're using a `Button`, a `Chip`, or an `Avatar`, you can expect the same API and behavior.

```tsx
/* Consistent sizing across components */
<Button size="lg" variant="primary">Click Me</Button>
<Chip size="lg" variant="secondary">Status</Chip>
<Avatar size="lg" src="..." />
```

### Type Safety

Moto UI is written in TypeScript. We provide exhaustive type definitions for all components, enabling robust IntelliSense, auto-completion for variants and tokens, and compile-time error detection.

```tsx
import { ButtonProps } from "@moto-ui/react";

/* Type-safe variants and sizes */
<Button
  variant="primary" // Autocomplete: "primary" | "secondary" | "tertiary"
  size="md"        // Type checked: "xs" | "sm" | "md" | "lg" | "xl"
/>

/* Easy to extend */
interface CustomButtonProps extends ButtonProps {
  isLoading?: boolean;
}
```

### Developer Experience (DX)

We believe a library should be a joy to use. This means providing clear, predictable APIs, helpful error messages, AI-ready documentation, and a comprehensive Storybook playground for visual testing.
